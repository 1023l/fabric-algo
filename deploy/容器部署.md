# fabric-algo Docker 容器部署

把算法侧服务打包成单一容器：**Web/算法 API + TRT 推理 + 模型管理（上传即转换）**。
容器内不需要 conda、不需要 paddle——rec 的 ONNX 导出在训练平台侧完成后随模型包携带。

## 0. 前置条件（目标机）

1. NVIDIA 驱动（CUDA 12.x 兼容，一般 550+）
2. Docker + nvidia-container-toolkit（一键脚本可用旧套件 `deploy/install-docker.sh` 的思路，或：
   `curl -fsSL https://get.docker.com | sh && sudo nvidia-ctk runtime configure --runtime=docker && sudo systemctl restart docker`）
3. 验证 GPU 可见：`docker run --rm --gpus all nvidia/cuda:12.5.1-runtime-ubuntu24.04 nvidia-smi`

## 1. 目录与文件

目标机只需要 fabric-algo 整个目录（模型 models/ 可为空，之后通过模型管理上传）：

```
fabric-algo/
├── *.py  tools/  static/  docs/
├── models/          # 挂载进容器（可空，上传模型后自动填充）
├── runs/            # 挂载进容器（检测输出）
└── deploy/
    ├── Dockerfile
    ├── docker-compose.yml
    ├── config.container.yaml   # 容器版配置（容器内路径）
    └── requirements-docker.txt
```

## 2. 构建与启动

```bash
cd fabric-algo
docker compose -f deploy/docker-compose.yml up -d --build
curl http://127.0.0.1:8001/health      # {"status":"ok"}
```

打开 `http://<IP>:8001/` 即是操作页面（与裸机部署完全一致）。

## 3. 模型上线（两种方式任选）

**方式 A：页面「模型管理」上传**（推荐）
- 训练平台「一键导出3个模型」→ 下载 zip → 页面底部上传
- 容器内自动构建 TRT engine（首个 engine 约 1 分钟，计时缓存后约 7 秒）→ 热替换生效

**方式 B：直接放 engine 文件**
- 把在其他机器构建好的同名 engine 拷到 `models/{fabric,text,rec}/`，再写 `models/current.json`：
  ```json
  {"fabric": "fabric20260828V2", "text": "text20260831V1", "rec": "rec20260828V3"}
  ```
- 重启容器：`docker compose -f deploy/docker-compose.yml restart`
- ⚠️ engine 绑 GPU 架构：只有同架构 GPU 之间才可拷贝（如都是 4090）

## 4. 数据在哪

| 内容 | 位置（宿主机） | 说明 |
|---|---|---|
| 模型/engine | `fabric-algo/models/` | bind mount，删容器不丢 |
| 检测输出 | `fabric-algo/runs/` | bind mount |
| TRT 计时缓存 | docker 卷 `trt_cache` | 重建 engine 提速 |
| 工具日志 | docker 卷 `trt_export` | `docker volume inspect` 找路径 |

## 5. 常用运维

```bash
docker logs -f fabric-algo                     # 服务日志
docker exec -it fabric-algo bash               # 进容器（tools/ 脚本可直接跑）
docker compose -f deploy/docker-compose.yml down   # 停止（卷保留）
docker compose -f deploy/docker-compose.yml up -d --build  # 代码更新后重建
```

## 6. 硬限制（同裸机部署）

- TRT engine 不可跨 GPU 架构 / TRT 版本 / **操作系统**（Windows 构建的 engine 在 Linux 容器加载会报
  `Platform specific tag mismatch`）；容器把 TRT 版本钉死（11.2.1.2）
- 跨平台/跨机器部署时在容器内重建 engine（ONNX 已随 models/ 携带）：
  ```bash
  # 服务容器 crash-loop 时先 stop，用一次性容器跑（重建会覆盖同名旧 engine）
  docker compose -f deploy/docker-compose.yml stop
  docker compose -f deploy/docker-compose.yml run --rm fabric-algo \
      python tools/build_engine.py --model all --force
  docker compose -f deploy/docker-compose.yml up -d
  ```
- TensorRT 单进程约束：uvicorn workers=1（镜像 CMD 已固定），不要改多 worker
- 首次上传模型时容器内构建 engine 需要 GPU，构建期间旧 engine 不受影响（试加载成功才热替换）
- 冒烟测试：`docker exec fabric-algo python tools/api_smoke.py --image /app/runs/infer/某帧.jpg`
  （接口前缀为 `/api/algo`，config.smoke.base 已含；注意 text 模型只对布片裁剪图出框，整帧 0 框属正常）
